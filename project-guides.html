Moira Network

A custom modded survival server with 100+ curated mods, custom economy, and unique gameplay mechanics.

01

Server Infrastructure

Set up a dedicated server using Kinetic Hosting with a Forge 1.20.1 base. Configured JVM flags for optimal garbage collection with 8GB allocated RAM:

-XX:+UseG1GC -XX:+ParallelRefProcEnabled
-XX:MaxGCPauseMillis=200
-XX:+UnlockExperimentalVMOptions
-XX:+DisableExplicitGC -XX:G1NewSizePercent=30
-XX:G1MaxNewSizePercent=40
-XX:G1HeapRegionSize=8M
02

Mod Curation & Compatibility

Curated 100+ mods through a rigorous batch testing process. Mods were added in groups of 8-10, tested for:

  • Registry synchronization errors
  • Mixin conflicts between mods
  • Client-server parity issues
  • Memory footprint per mod

Used Sinytra Connector to bridge select Fabric-only mods (like certain UI mods) into the Forge environment.

03

Configuration & Balancing

Custom-configured every mod's settings for balanced multiplayer gameplay:

  • Tuned ore generation rates to prevent resource flooding
  • Balanced mob spawn rates across modded dimensions
  • Set up custom recipe modifications via CraftTweaker
  • Configured permission nodes for each mod's commands
04

Crash Resolution & Stability

Systematically debugged crashes using log analysis:

  • Resolved IndexOutOfBoundsException in registry sync
  • Fixed conflicting Mixin patches between mods
  • Identified and removed mods causing memory leaks
  • Created world backup automation scripts

Equestrian Overhaul

A comprehensive modpack featuring custom horse mechanics, new biomes, and a complete equestrian gameplay experience.

01

Concept & Mod Research

Researched and evaluated 200+ mods to find the perfect combination for an equestrian-themed experience:

  • Horse-related mods: Swem, Horse Combat Controls, Realistic Horse Genetics
  • Biome mods: Biomes O' Plenty, Terralith for varied terrain
  • Quality-of-life: JEI, JourneyMap, Inventory Sorting
  • Visual: Shader compatibility, custom resource packs
02

Fabric-to-Forge Bridging

Several essential mods were Fabric-only. Used Sinytra Connector and Forgified Fabric API to bridge them:

# Bridged Fabric Mods:
- Mod Menu (UI navigation)
- Cloth Config (settings screens)
- Custom HUD elements
- Certain entity renderers

# Required compatibility layer:
sinytra-connector-1.0.0-beta.42+1.20.1.jar
forgified-fabric-api-0.91.0+2.0.8+1.20.1.jar
03

Phase-Based Testing

Implemented a 6-phase batch testing strategy to ensure stability:

  • Phase 1-2: Core mods and dependencies (Forge, APIs, libraries)
  • Phase 3-4: Content mods in batches of 10, testing each batch
  • Phase 5: Fabric-bridged mods with extra compatibility checks
  • Phase 6: Client-side mods, shaders, and resource packs

Each phase required a clean server start, 10-min play session, and logout/login cycle.

04

Modpack Distribution

Packaged the modpack for easy installation:

  • Created CurseForge-compatible manifest
  • Wrote custom install scripts for server operators
  • Built a config preset system for different play styles
  • Documented all mod versions and dependencies

AutoCraft Suite

A plugin suite for automated server management with Discord integration.

01

Plugin Architecture

Designed as a modular plugin suite using Paper API and Java 17:

autocraft-suite/
├── autocraft-core/        # Shared utilities
│   ├── ConfigManager.java
│   ├── DatabasePool.java
│   └── MessageFormatter.java
├── autocraft-scheduler/   # Task scheduling
│   ├── RestartTask.java
│   ├── BackupTask.java
│   └── CronParser.java
├── autocraft-analytics/   # Player tracking
│   ├── SessionTracker.java
│   ├── PlaytimeCommand.java
│   └── StatsAPI.java
└── autocraft-discord/     # Discord bridge
    ├── BotManager.java
    ├── ChatSync.java
    └── WebhookHandler.java
02

Scheduled Restart System

Built a flexible restart scheduler with player-friendly warnings:

// RestartTask.java
@Override
public void run() {
  int[] warnings = {300, 60, 30, 10, 5};
  for (int secs : warnings) {
    scheduler.runTaskLater(plugin, () -> {
      broadcast("&cServer restart in "
        + secs + "s");
    }, (totalDelay - secs) * 20L);
  }
  scheduler.runTaskLater(plugin, () -> {
    Bukkit.shutdown();
  }, totalDelay * 20L);
}
03

Discord Integration

Integrated JDA (Java Discord API) for two-way chat sync:

  • Real-time Minecraft ↔ Discord chat bridge
  • Server status embeds (player count, TPS, uptime)
  • Slash commands: /status, /players, /tps
  • Event webhooks for join/leave/death messages
04

Player Analytics Dashboard

Built a MySQL-backed analytics system tracking:

  • Session duration and playtime leaderboards
  • Unique player counts per day/week/month
  • Peak concurrent player tracking
  • Custom events (blocks mined, mobs killed, etc.)

Data exposed via a REST-like API for external dashboards.

05

Build & Deploy Pipeline

# Build with Gradle
./gradlew shadowJar

# Deploy to server
scp build/libs/autocraft-suite-1.0.jar user@server:/plugins/

# Hot-reload (Paper)
/plugman reload AutoCraftSuite

# Run tests
./gradlew test --info
